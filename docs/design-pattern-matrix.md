# Nine GoF patterns - implemented design and justification

**9/9 implemented:** State (S1); Factory Method, Abstract Factory, Builder, Decorator (S2); Strategy (S3); Adapter, Facade, Observer (S4). BookingIntegrationTest demonstrates all nine through the application API. S5 console now demonstrates the same pipeline through Main composition.

S7A adds a read-only JavaFX presentation adapter on feature/javafx-ui. Main.createContext supplies the same facade graph to both entry points; desktop demonstration seed commands traverse the existing creators, builder, mode families, reminder decorator, strategy, state, facade, observers and calendar adapter. All nine implementations and original behavioral tests remain unchanged. S7A does not claim interactive desktop booking/lifecycle coverage; that is S7B after approval. See ui-review/S7A.md.

S7B, explicitly authorized after approval, adds interactive JavaFX booking and lifecycle flows using that same graph. DesktopController invokes existing decorator quotes, mode families, strategies and facade methods; immutable Appointment operations determine eligible lifecycle actions without duplicating State rules. DesktopControllerTest and the opt-in DesktopS7BCheck verify real presentation workflows. No pattern implementation changed. See ui-review/S7B.md for final evidence and limits.

## Implemented integrated workflow (S4)

A test or the S5 console submits BookingRequest and a stable command ID to BookingFacade. AppointmentAssembler resolves catalog references and the injected service-kind creator; the request supplies mode factory, decorator chain and availability policy. Abstract Factory provides paired mode products. Decorator chain computes optional fees/instructions. Builder validates the complete spec and Factory Method constructs the correct PENDING subtype. Atomic repository reserve invokes domain hard rules and Strategy against the latest schedule, persists the aggregate, and appends its immutable event with revision and global sequence. Dispatcher invokes Observer consumers in order and Adapter synchronizes the simulated calendar. Facade returns a committed view plus delivery warnings. Later confirm/cancel/complete/reschedule calls use the same facade/repository/event path and invoke State behavior. This demonstrates all nine patterns in one lifecycle rather than separate demos.

See architecture.md for authoritative transaction, timezone and event failure semantics. See UML for the implemented collaborator graph. Adapter and Observer evidence: CalendarObserverTest. Facade, failures, concurrency and all-nine-pattern evidence: BookingIntegrationTest. Calendar conflicts are post-commit warnings under the documented local-authority policy.


## S6.1 package ownership correction

Factory Method products Appointment, ConsultationAppointment and ServiceAppointment, Builder capability ValidatedAppointmentSpec, and intrinsic AppointmentRules now live in `domain.appointment`. Shared values remain in `domain.model`. State, mode families and decorator implementations retain their packages and behavior. The command/receipt coordinator is now `application.CommittedEventDispatcher`; Observer contracts remain in `application.event`. Six class names change package qualification only; constructors, method behavior and all nine roles/interactions remain intact.
