## Historical S6 architecture and code quality findings

No critical correctness defect found in the inspected supported workflows. No production refactoring was justified. Constructor injection, immutable aggregate replacements, defensive collection copies and instance-owned synchronization are used consistently. Main is the application composition root; creation of per-request mode/decorator/strategy values in the console is selection logic, not a second service container.

SOLID/DRY: creation, scheduling, lifecycle, delivery and presentation have separate responsibilities. Ports invert infrastructure dependencies. Strategy/creator/decorator/observer substitutions are exercised by tests. Sealed state/product hierarchies constrain extension deliberately. Repository is a relatively broad port combining immutable catalog reads, reservation commands and event reads; this is an academic-scale interface-segregation tradeoff. Shared AppointmentRules/ValidatedAppointmentSpec enforce business validation; repeated validation at commit is necessary to prevent stale advisory results. Console repeats display prices/hours from the fixed demo configuration, but does not authorize reservations using those strings.

The new `ArchitectureTest` uses JDK jdeps over compiled classes, so wildcard imports and fully qualified references cannot hide forbidden layer dependencies. It enforces domain -> domain/JDK, application -> application/domain/JDK, infrastructure and presentation -> application/domain/themselves/JDK, and Main's composition exemption. Presentation cannot access AppointmentRepository or CommittedEventDispatcher. A second test rejects mutable static fields and nontrivial static object holders. This is not a full static analyzer or proof against reflection.

**Historical N02 qualification (resolved by S6.1): package cycles existed.** Layer dependencies are acyclic, but `domain.model` mutually references `domain.state`, `domain.mode` and `domain.addon`; `application` and `application.event` mutually reference facade/result/dispatcher types. These are real intra-layer package cycles. The literal requirement for no circular dependencies is therefore not fully met if it means every Java package. No dependency cycle crosses architectural layers and no cyclic constructor injection was found. Removing these cycles would require package/type restructuring beyond a minimal critical fix; they are disclosed for assessment, not silently marked compliant.

Atomicity: InMemoryAppointmentRepository's instance ReentrantLock covers latest-state read, one clock capture, validation, replacement, revision and event append. Failed reserve/reschedule/transition leaves stored snapshots/events unchanged. Immutable read snapshots escape safely. Custom strategy callbacks execute under that lock and must be pure/nonblocking; reentrant writes reject. Dispatcher serializes facade commands and post-commit delivery outside the repository lock. Subscriber RuntimeExceptions are isolated, and calendar errors become committed-result warnings. JVM Errors, crashes and callbacks waiting for other command threads are outside guarantees. One dispatcher per repository is mandatory.

Additional limits: in-memory unbounded event/receipt collections; no automatic delivery retries or durable exactly-once claims; linear scans/whole-store locks; English console and wide tables. Invalid timezone configuration prints a clear error but Main returns normally (exit 0); this is a low-severity command-line diagnostic limitation, not a claim that configuration succeeded. Extreme historical zone transitions and every terminal width are not exhaustively tested.
